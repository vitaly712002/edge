# edge — общий reverse-proxy сервера

Единственный Caddy на сервере. Владеет портами 80/443 и TLS-сертификатами,
маршрутизирует домены к приложениям. От приложений не зависит — связь только
через общую сеть `web` и доменные блоки в [Caddyfile](Caddyfile).

## Принцип

```
Интернет ──80/443──▶ edge (Caddy) ──сеть "web"──┬─▶ chatkeeper
                                                 ├─▶ secure-ask-bot
                                                 └─▶ secure-ask-web
```

- **edge** знает про приложения (их домены и alias'ы) — это осознанная плата за
  простой центральный конфиг.
- **Приложения** не знают ни про edge, ни друг про друга — только подключаются к
  сети `web`.
- Сеть `web` создаётся вручную и не принадлежит ни одному проекту.

## Первый запуск

```bash
# 1. Создать общую сеть (один раз на сервер).
docker network create web

# 2. Указать свой домен (файл .env в git не попадает).
cd ~/projects/edge
cp .env.example .env
nano .env            # BASE_DOMAIN=твой-домен.ru

# 3. Поднять прокси.
docker compose -p edge up -d
```

> Реальный домен хранится только в `.env`. В `Caddyfile` он подставляется
> как `{$BASE_DOMAIN}`, поэтому конфиг можно спокойно держать в git.

## Добавить новый сайт

1. Приложение подключить к сети `web` с уникальным alias (см. его compose).
2. Добавить блок в [Caddyfile](Caddyfile):
   ```caddy
   myapp.{$BASE_DOMAIN} {
       reverse_proxy myapp:8080
   }
   ```
3. Применить без простоя:
   ```bash
   docker exec edge-caddy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
   ```

## Требования к приложениям

- Подключаться к внешней сети `web` с уникальным alias.
- Отдавать свой HTTP (API и, если есть, статику) на известном порту.
- Не публиковать порты на хост и не поднимать свой Caddy.
